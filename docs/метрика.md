# Яндекс Метрика: схема целей

Номер счётчика пока не задан. Когда он появится, его нужно положить
в переменную репозитория `YM_ID`:

**Settings → Secrets and variables → Actions → Variables → New variable**
Имя `YM_ID`, значение — номер счётчика. Следующая сборка подхватит его сама,
трогать код не нужно.

Пока переменной нет, счётчик не грузится вообще, а вызовы целей в режиме
разработки пишутся в консоль — видно, что схема работает.

## Цели

Создать в Метрике как **JavaScript-событие** с этими идентификаторами:

| Идентификатор  | Когда срабатывает                        | Зачем                                          |
| -------------- | ---------------------------------------- | ---------------------------------------------- |
| `quiz_start`   | нажата «Рассчитать стоимость»            | сколько людей вообще начали                     |
| `quiz_step_1`  | отвечен вопрос 1 «Что нужно сделать»     | ↓                                               |
| `quiz_step_2`  | отвечен вопрос 2 «Для чего сайт»         | ↓                                               |
| `quiz_step_3`  | отвечен вопрос 3 «Что уже есть»          | ↓                                               |
| `quiz_step_4`  | отвечен вопрос 4 «Когда нужен результат» | ↓                                               |
| `quiz_step_5`  | отвечен вопрос 5 «Сколько страниц»       | ↓                                               |
| `quiz_step_6`  | отвечен вопрос 6 «Что важнее»            | ↓                                               |
| `quiz_step_7`  | отвечен вопрос 7 «Бюджет»                | на каком вопросе людей теряем                   |
| `quiz_back`    | человек вернулся назад                   | какой вопрос непонятен                          |
| `result_shown` | показана вилка стоимости                 | дошли до главного обещания                      |
| `form_start`   | человек начал заполнять форму            | цифра не отпугнула                              |
| `lead_sent`    | заявка ушла                              | **главная цель для Директа**                    |
| `lead_failed`  | отправка не удалась                      | потери не по вине человека                      |

Цель на каждый вопрос — не избыточность. Главная цифра первого месяца платного
трафика это не «сколько заявок», а «на каком вопросе люди уходят»: без цели
на каждом шаге вы этого не увидите, а увидите только общую воронку.

## Что смотреть в первую очередь

1. `quiz_start` → `quiz_step_1`. Большая просадка здесь значит, что первый
   вопрос отпугивает.
2. `quiz_step_6` → `quiz_step_7`. Просадка на вопросе о бюджете — самая частая.
   Под вопросом стоит подпись, что бюджет не влияет на расчёт; если всё равно
   течёт, вопрос стоит двигать или убирать.
3. `result_shown` → `form_start`. Просадка здесь значит, что цифра не устроила:
   либо вилка слишком высокая для этого трафика, либо трафик не тот.
4. `form_start` → `lead_sent`. Просадка здесь — проблема формы, а не оффера.

## Где это в коде

`src/lib/metrika.ts` — единственное место, где перечислены цели (`GOALS`)
и живёт загрузка счётчика. Счётчик грузится не сразу, а в простое браузера
или по первому касанию: сторонний скрипт не должен портить скорость загрузки,
за которую вы платите ценой клика.
